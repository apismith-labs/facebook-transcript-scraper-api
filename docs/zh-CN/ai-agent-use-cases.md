# 面向 AI 智能体的用法

[English](../ai-agent-use-cases.md)

这个 Actor 只返回文本、带时间戳的分段和元数据，不做摘要、分类或分析——那些属于你的模型。本页介绍几种与
这个返回结构天然契合的做法。

## 为检索做准备（RAG）

1. 用批量执行器提交链接，把 `rowId` 当作稳定的文档主键。
2. 每个分段连同 `start`/`end` 一起存储，引用才能定位到具体时间点。
3. 按 30–60 秒切块，相邻块重叠一个分段。
4. 把 `url`、`title`、`nickname`、`duration` 存为可过滤的元数据。
5. 跳过状态不是 `success` 的条目，不要索引空字符串。

为什么用分段而不是整篇文本：当切块对应一段连贯的口语内容时，检索质量更好；`[02:14]` 这类引用也能被人直接
回看核实。

## 内容研究与竞品分析

- 对比不同创作者前 15 秒的钩子结构。
- 用 `分段数 / 时长` 粗略衡量语速。
- 先对转写文本做主题聚类，再与 `playCount`/`reactionCount` 关联看表现——但要记住这些只是某一时刻的快照。

## 审核与合规检查

- 二次发布之前，先按政策类别筛查转写内容。
- 保留原始条目，让审核结论日后可追溯。
- 把 `no_transcript` 当作“需要人工复核”，而不是“干净”。

## 客服与 FAQ 挖掘

问答类视频里常有反复出现的问题。有了分段级文本，就可以抽取问答对，再导入知识库。

## 本地化

逐段翻译以保持时间轴，然后重新生成字幕。本仓库不产出 SRT/VTT，但 `segments` 足够你自行拼装：

```
序号
HH:MM:SS,mmm --> HH:MM:SS,mmm
文本
```

## 智能体工作流形态

```
链接清单（CSV）
  -> 批量执行器（先计划，再执行）
  -> 结果 JSON（status、text、segments、原始条目）
  -> 过滤 status == success
  -> 切块 + 向量化 + 元数据
  -> 检索 / 摘要 / 审核
```

## 建议接入的护栏

- 限制单个任务的链接数量和单 Run 费用。
- 没有转写文本的行直接拒绝，不要把空上下文喂给模型。
- 任何生成的结论都附上来源 `url`，保证可回溯。
- 创建结果不明确之后，绝不能允许智能体再建一个替代 Run；给它一个 `resume` 工具，或者要求人工核对。
- 限制并发；并发越高，同时在跑的计费 Run 越多，撞 429 的概率也越大。
