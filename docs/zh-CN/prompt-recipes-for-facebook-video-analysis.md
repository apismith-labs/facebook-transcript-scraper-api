# 针对 Facebook 视频转写的提示词配方

[English](../prompt-recipes-for-facebook-video-analysis.md)

这些提示词假设你已经拿到一个 `success` 结果，含 `text`、`segments`、`title`、`nickname`、`url`。它们是
起点，不是效果保证。提示词用中文给出；如果你的模型对英文提示更稳，可自行改写，只保留约束条件。

## 1. 带时间戳的摘要

```
下面是一段以带时间戳分段形式给出的视频转写。
请写一段摘要，最多 8 条。
每条末尾都必须标注支撑该条内容的分段起点时间，格式为 [MM:SS]。
不要补充转写里没有的事实。
如果转写内容本身不连贯，直接说明，不要猜测。
```

## 2. 钩子与结构分析

```
只分析这段转写的前 30 秒。
返回 JSON：
{
  "hook_type": "question|claim|story|demo|other",
  "first_sentence": "...",
  "promise": "...",
  "payoff_timestamp": "MM:SS 或 null",
  "notes": "..."
}
```

## 3. 带证据的论点抽取

```
抽取出说话人提出的所有事实性主张。
每一条返回：
- 主张内容
- 支撑原文（逐字引用，不超过 25 个词）
- 时间戳
- 置信度：high|medium|low，仅依据转写对该主张的支持清晰程度判断
不要包含观点或反问句。
```

## 4. 保持分段对齐的翻译

```
把每个分段的文本翻译成 {target_language}。
分段数量与顺序必须完全一致，不要合并或拆分分段。
人名、数字、产品名保持原样。
返回 JSON：[{"start": number, "end": number, "text": "译文"}]
```

## 5. 内容再利用

```
仅依据这段转写，起草：
1. 一篇 120 字的 LinkedIn 帖文
2. 五条短帖（X）
3. 一段 6 行的邮件简报小节
保持说话人的视角。不要编造统计数据或引语。
转写中不清楚的地方请用 [不清楚] 标注。
```

## 6. 审核预筛

```
按以下类别对转写分类：骚扰、医疗建议、金融建议、露骨内容、无。
返回 JSON，包含类别、严重程度（none|low|medium|high），以及一段带时间戳的简短引用作为依据。
如果转写为空，类别返回 "unknown"。
```

## 7. 问答抽取

```
找出这段转写中的问答对。
返回 JSON：[{"question": "...", "answer": "...", "timestamp": "MM:SS"}]
只保留视频中确实提出并回答了的问答对。
```

## 8. 元数据整理

```
根据标题与转写，给出：
- 一个 60 字以内的描述性标题
- 5 个主题标签
- 一句话简介
不要用标题党。不要声称任何转写中没有依据的内容。
```

## 实践建议

- 需要时间戳时，喂 `segments`，而不是只喂整篇文本。
- 明确告诉模型这是自动识别的转写，可能存在识别错误。
- 输出要接下一步处理时，要求返回 JSON，并在存储前做校验。
- 状态为 `no_transcript` 或 `actor_error` 的转写，不要发给模型。
