# Live run record — 2026-10-28

The audit of the same date was built from the pinned build's schema, the Store README, and the
public API metadata. This page records **19 controlled paid Runs** that replaced those
schema-only assumptions with observed behaviour: six of the seven URL forms the clients accept, all
four reference clients, and one batch execution.

Total charge for this round: **$0.0595** (9 successful Runs at $0.0055, 10 unsuccessful Runs at
$0.0010; unsuccessful Runs are billed for the dataset item only, never for `speech2text`).

Every Run used build `0.0.18` / `fZIlpYENof2jYqIJc`, the constants pinned in all four clients, and
every Run was created with a per-Run charge cap of `$0.10` enforced **before** the `POST`.

### What the matrix proves

1. **Four of the six shipped forms extract correctly**: `share`, `watch`, `page_video`, and `reel`
   all returned the same 42.261 s video, the same page (`ttvnews` / 台視新聞台), and a populated
   `text` + `segments`. The submitted URL is echoed verbatim in the item's `url` field; no form is
   rewritten upstream.
2. **IDs are namespaced, and the Actor does not correct for it.** `1612151150942907` is the *post*
   ID from the Run log's `id`; `1131784255863745` is the *video* ID from the log's `efg`
   attribute. Feeding the post ID to `/reel/` or `/watch/?v=` produces `actor_error`
   (`errMsg: 'no audio url found'`) rather than a redirect or a clearer message. Callers must pass
   IDs that Facebook itself puts in that URL shape.
3. **`/videos/<id>/` needs a page context.** The bare form failed three times with the Actor
   reporting Facebook's `Not Found` body, while `/ttvnews/videos/<same id>/` succeeded in the same
   minute. The difference is the path, not the ID: Facebook only serves the video page under a
   profile or page owner. `page_video` is therefore the form to prefer for page uploads.
4. **`/video.php?v=` is effectively dead at Facebook.** All three attempts returned Meta's
   `Sorry, something went wrong.` error page while `/watch/?v=` with the identical ID succeeded.
   The client still accepts the form (it is a documented legacy shape), but it should not be
   advertised as working.
5. **`fb.watch` remains untested.** A short code cannot be derived from a video ID and this
   environment cannot open Facebook to mint one. The validator accepts the form and forwards it
   unchanged; the Actor-side resolution is still unproven.

## 4. Defects found by going live, and fixed

| Defect | Impact | Fix |
| --- | --- | --- |
| Java `readDotEnv` stripped only double quotes | A `.env` written as `APIFY_MAX_TOTAL_CHARGE_USD='0.10'` — the style this repository's own `.env` uses — failed validation with `must be a finite positive number`, so the Java CLI could not make a single live call | quote stripping now accepts `'…'` and `"…"`; parser extracted to `parseDotEnvLines` and covered by tests |
| Go `--json` omitted `datasetComplete` | A caller switching from Python/Node.js/Java to Go silently lost the truncation signal | key added to `renderJSON`; regression test asserts the full documented key set |
| Java emitted `""` for absent `error`, `title`, `nickname` | Callers checking `is null` behaved differently per language | blank optional strings are now `null`, matching the other three clients |

## 5. The Actor fails transiently, and it looks like a business result

Two `watch` Runs on a URL that had already succeeded returned within seconds:

```
{ code: -4, msg: '获取失败了', data: { b2: '<html>…Sorry, something went wrong…</html>' } }
```

The Run still succeeds, the dataset still contains one item, and the item carries
`errMsg: 'no audio url found'` with `duration: 0`. The client therefore reports `actor_error`
(exit 4) — indistinguishable from a genuine "this video has no audio" outcome.

Observed rate: **2 of 11 otherwise-valid attempts (~18 %)** in this round. Callers that need
reliability must treat `actor_error` with `errMsg: 'no audio url found'` as **retryable**, and
retry by creating a **new** Run (the client never retries a create on its own, and a resumed Run
will not re-run the extraction). This is documented in
[error handling and retries](../error-handling-and-retries.md).

The same failure mode means a single failed Run is not evidence that a URL form is unsupported;
the two forms above were each rejected three times with a distinct Facebook-side body (`Not Found`
and the generic error page) before being recorded as unsupported.

## 6. Billing behaviour confirmed on failures

- An unsuccessful Run still writes one dataset item and is charged **$0.0010**.
- `speech2text` is charged **only when transcription produced text**; none of the ten unsuccessful
  Runs shows a `speech2text` event.
- A 42.261 s video is billed as one full minute ($0.0045) plus the item ($0.0010) = $0.0055, which
  matches the shipped estimator to the cent.

## 7. Still not covered

- `fb.watch` short links (no code available in this environment).
- A classic page video uploaded before reels existed — the `page_video` and `videos` results above
  come from a reel-sourced ID, so a legacy upload may behave differently on the bare
  `/videos/<id>/` path.
- A genuinely private, deleted, or region-locked video; a video with no speech at all.
- Whether `errMsg` can coexist with a non-empty `text`.
- Dataset cardinality beyond one item per Run.

## 8. Content handling

The transcript is third-party content captured from a public post. It is **not** reproduced here,
and neither are the signed CDN links (`videoUrl` / `audioUrl` carry expiring `oe=` parameters). The
full responses and the exact input URLs stay in the local, git-ignored
`sample-output/generated/` directory. Only identifiers, counts, units, and billing figures are
recorded in this repository — the parts that are load-bearing for the client code.

## 9. Reproduce

All commands are read-only except the first, which creates a Run and is capped before the `POST`:

```bash
python3 examples/python/single_url.py '<facebook video url>' \
  --max-total-charge-usd 0.10 --require-charge-cap --json

python3 scripts/check_apify_run.py <RUN_ID>
curl -s -H "Authorization: Bearer $APIFY_TOKEN" \
  https://api.apify.com/v2/actor-runs/<RUN_ID>/log?format=text
```
